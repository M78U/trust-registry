# Authenticated local review and release approval

The exact snapshot and complete reviewed dossier from CA-REVIEW.md are inputs. The independently provisioned authority configuration is strict JSON with schemaVersion 1, releaseThreshold >=2 and keys [{id,role,publicKey}]. publicKey is standard base64 raw 32-byte Ed25519 public key (not PEM or SPKI). Roles SOURCE_IDENTITY (source tasks), REVIEW (redistribution, scope, disclosure) and RELEASE (approval only); unique IDs and unique raw public keys across all roles. At least one source and one review key, at least two release keys, 32 total. No default keys. Independently distribute the SHA-256 of exact configuration file bytes and protect it against rollback. The verifier must not use an untrusted pin supplied by the candidate author. A pin proves configured key identity, not independent human identity or device possession. TUF role keys must be separate by operator practice; cross-config enforcement is future work.

All approvals use domain-separated Ed25519 over SHA-256 of deterministic Go JSON. Task signature binds authority digest, exact snapshot digest and entire approved attestation (requirement, reviewer, time, evidence, note). Release signature binds exact snapshot/dossier digests, sequence, authority digest, explicit window, sorted complete task signatures and approver ID. Release signature list excluded from message so multiple approvers sign the same set; reviewers cannot add or change tasks once release signing starts. Distinct keys, exact task membership, role restrictions and threshold enforced. Local review gate and artifact hashes are rechecked at every step; evidence must be read by actual reviewers. Signature recording times are assertions; no external trusted timestamp. Approval window <=24 hours within snapshot validity, all review times at/before window start; authenticate checks current explicit UTC time in [from,until). No auto-publication or private key generation. Private signing keys read from local PKCS#8 PEM; never put in repository. New output path only. Approval file canonical compact Go JSON + LF; never edit manually. Dossier may be pretty printed.

Use shared flags on each command: --dossier FILE --evidence DIR --authority FILE --authority-sha256 INDEPENDENT_PIN --at CURRENT_RFC3339 followed by exact SNAPSHOT path (flags before path).
* review prepare-approval --until END_RFC3339 --out approval-0.json: creates empty signature collection after local gate.
* review sign-task --approval approval-0.json --id TASK_ID --key REVIEWER_PKCS8.pem --out approval-1.json: repeat for each task, use latest file and unique output.
* review approve-release --approval LATEST.json --id APPROVER_ID --key RELEASE_APPROVER_PKCS8.pem --out NEXT.json: repeat using distinct authorized release approvers until threshold met.
* review authenticate-approval --approval FINAL.json: verifies all signatures and local evidence; returns LOCAL_THRESHOLD_APPROVAL_VERIFIED and localReleaseApprovalVerified=true. releaseAuthorized=false, releaseAuthenticated=false, trustStatus=NOT_ESTABLISHED remain unchanged. No proof of legal rights or evidence conclusion by cryptography alone.

No key rotation/revocation, trusted timestamp, persisted anti-rollback state, cross-config TUF key separation or enforced publisher integration yet. Approval may be reused for the same exact snapshot during its validity window; this is not a one-time release ledger. Protect all local inputs, clock and pins. Never publish the private evidence or dossier. Synthetic test covers role confusion, duplicate keys and signers, threshold, tampering, expiry and dossier changes. Go tests not executed; automatic CI remains disabled.
