# Emergency local policy updates

Restrictions are explicit local candidate changes, not certificate revocation or authenticated emergency notices. ProposeRestriction is negative-only: SUSPENDED may have an optional end, DISTRUSTED is indefinite. Exact declared anchor and policy version, new ID, immediate effective time equal to recording time, reason and explicit audit references required. It clones the original document, appends an event, validates against the inventory and checks the resulting state. No write, release, global revocation or automatic root changes. Existing externally authored decisions retain their schema semantics.

Evaluate now also requires each positive decision and all its supporting reviews to be recorded strictly after the most recently recorded applicable known negative decision for that anchor. This blocks a positive decision scheduled before an emergency from later silently restoring authorization, even if the restriction expires. It applies to both suspension and distrust; a deliberate fresh review and explicit decision can reauthorize, so indefinite distrust is not an irreversible cryptographic revocation. Historical as-known evaluations do not see later-recorded restrictions. Negative decisions recorded later can affect retrospective evaluation. This is a conservative change to local evaluation semantics, not a new status or schema.

CompareRevision compares exact same policy definition and immutable event prefixes, rejects deletion, mutation and reorder, requires newly appended event recording times strictly later than all baseline events, and returns compact JSON+LF document digests. ValidateTransition checks both explicit complete policy collections against the current inventory and requires all previous versions retained. New versions of existing IDs must be higher than baseline maximum, preserve purpose/jurisdiction and start without pre-authorized anchors; new IDs also start without positive decisions. Version bumps do not inherit trust automatically. This is not an authenticated append-only ledger: a caller must protect and supply the authentic complete baseline. Exact policy versions remain separately selectable and restrictions affect only the targeted version and role. A later explicit revision of another version can authorize independently; global cross-policy/stream emergency enforcement, release integration and signed monotonic ledger are not implemented. Do not mistake a transition check for authenticated publication.

```sh
trust-registry policy restrict --registry ./local-registry --file old.json --id incident-001 --fingerprint SHA256 --status SUSPENDED --at 2026-11-27T10:00:00Z --reason "investigate source incident" --review-ref incident-001 > proposed.json
trust-registry policy check-transition --registry ./local-registry --previous old.json --next proposed.json
```

Use a NEW output path (shell redirection can truncate files, never redirect to input). For multiple policy versions repeat previous/next flags with the complete sets. Use reliable actual recording time and independently reviewed references. CLI outputs local proposal only; review and publish through a separately authorized workflow. No automatic CI, Go tests added but not executed. No public CA data or keys.
