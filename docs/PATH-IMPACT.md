# Certificate path impact (local research)

Compare one local end-entity certificate under two independently pinned, fully integrity-validated research snapshots. Next sequence and creation time must increase. Explicit exact policy ID/version, purpose and identical jurisdiction required on both sides; missing or mismatched policy fails instead of choosing another version. Explicit evaluation and knowledge times (knowledge >= evaluation), DNS name only for server authentication. Same existing technical verification logic and local authorization; no OS roots, AIA, network or automatic trust. Snapshot windows relative to knowledge time are reported, including expired or not-yet-created snapshots; this is counterfactual analysis, not a freshness or installation claim.

```sh
trust-registry snapshot path-impact --previous old.json \\
  --previous-sha256 OLD_PIN --snapshot-sha256 NEW_PIN \\
  --certificate signer.cer --policy-id cn.document-signing --policy-version 1 \\
  --purpose document-signing --at EVALUATION_RFC3339 --known-at KNOWLEDGE_RFC3339 new.json
```

Optional --revocation-store PRIVATE_BASELINE uses one detached, validated observation set at the shared knowledge cutoff for both sides. Optional --next-revocation-store PRIVATE_REPLACEMENT requires baseline and evaluates the next snapshot again with the replacement set. Both are explicitly selected local stores, not authenticated or pinned revocation receipts. Read each store once per invocation (same object reused); never implicitly refresh. SAME_EVIDENCE_DIFFERENT_SNAPSHOT compares the first two evaluations, SAME_SNAPSHOT_DIFFERENT_EVIDENCE compares next with baseline vs replacement. Evidence replacement may omit records; this is a comparison, not a valid append-only evidence transition or proof of absence. An empty baseline can be an explicitly initialized empty store. Both stores are checked in full, including future-record integrity. Without evidence, revocation is NOT_CHECKED. With evidence, existing worst-risk all-returned-paths check excluding anchors applies; no valid technical path means NO_VALID_PATH. NON_REVOKED_INDICATIONS_ONLY is not a final GOOD. No business-purpose authorization or release authentication.

Reports include normalized chain fingerprints (hash of canonical ordered fingerprint list), chain additions/removals, authorization and intermediate declaration differences, path/usage status, revocation aggregate and per-chain/pair status, historical revoked flags, observation identity and record digests. Pair result changes and observation metadata changes are separate; no raw evidence, source strings, leaf DER, private reviewer reasons or DNS name exported. Chain IDs are sorted, order within chain preserved. No causal claim about actual signed documents; no signature or document verification, no proof that all path options were found. Re-evaluate affected paths independently. Up to three evaluations, 256 returned chains per state, depth 64, 4 MiB canonical report; existing CA and evidence limits apply; fail rather than truncate. Local calculations only, zero Cloudflare service operations/new bindings. Synthetic test with real generated leaf/root/CRL exercises isolated evidence change and path loss. Go tests not executed; locked validation remains pending. No SigLens code change, no deployment.
