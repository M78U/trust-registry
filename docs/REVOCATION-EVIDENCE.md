# Offline revocation evidence

The revocation package adapts the strict CRL and OCSP parsing profiles from M78U/siglens commit 4a4ce7d5978ed2be3ad984dc54b572750d2b6c8c, internal/trust/crl.go and ocsp.go. No dependency on SigLens, no new Go modules. First verify the explicit certificate/issuer direct signature, raw issuer DN, AKI/SKI where present, CA and signing constraints. This is NOT full certificate path validation; issuer is not authenticated as trusted. CRL supports complete direct-issuer lists with AKI and number, explicit CRLSign, allowed strong signature algorithms including SM2, issuer certificate valid at thisUpdate, unique serials and supported reason codes. Reject delta, indirect/partitioned lists, issuing distribution point, unsupported extensions and weak signatures. OCSP supports direct issuer BasicOCSPResponse, one CertID (issuer name/key hash and serial), responder by name/key, optional exact issuer certificate, mandatory nextUpdate, allowed RSA/ECDSA/SM2 signatures, no extensions or delegated responders. SHA-1 is allowed for identifier hashing only. Inputs bounded; CRL aggregate 16 MiB, 16 lists, 50,000 entries; OCSP 16 responses, 1 MiB each, 16 MiB total. No network/AIA, no auto fetch, no cache or persistence. DER/PEM bytes stay local.

The evaluation time must be in [thisUpdate,nextUpdate) for CRL or [producedAt,nextUpdate) for OCSP. Explicit knowledge cutoff filters evidence by signed issuance time, not proven receipt time. Authenticated later-issued or expired revoked assertions with revocationTime at/before evaluation are separately reported as historical indications, never promoted into contemporaneous proof. A current revoked assertion dominates contradictory evidence; conflict is separately marked. No final GOOD verdict: serial absence or authenticated GOOD is NON_REVOKED_INDICATIONS_ONLY, ambiguity/unknown/missing evidence is INCOMPLETE_SUPPLIED_EVIDENCE, contradictory assertions are flagged. No distribution point coverage, freshest evidence or non-revocation proof. A valid evidence report does not authorize roots, prove historical receipt, modify policy or establish release trust.

```sh
trust-registry revocation --issuer issuer.cer --at 2026-11-27T00:00:00Z --known-at 2026-11-27T00:00:00Z --crl issuer.crl --ocsp response.der signer.cer
```

Repeat --ocsp for multiple files. JSON report followed by nonzero exit for revoked/conflicting/incomplete; zero is inspection success only, not trust. SDK LoadCRLBytes, LoadOCSPBytes and EvaluatePair. No persisted signer or evidence bytes. This is a pair-level engine; integrate with explicit verified paths separately, excluding anchors from normal revocation checks. Synthetic tests adapted from SigLens, SM2 CRL and ECDSA OCSP, time cutoff, wrong issuer/serial/signature and conflict. Automatic CI is disabled and Go execution remains pending.
