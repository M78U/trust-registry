# Local research snapshot installation

Not a production updater or trusted CA distribution. The caller chooses a private, dedicated local directory and independently pins the Ed25519 public keys and threshold. Explicit bootstrap is required for first installation only. Subsequent installs and loads use exactly the same key configuration (order-independent key IDs + threshold digest); key rotation is unsupported. A reliable explicit current UTC time is required. Old expired snapshots can be replaced by newer valid snapshots; expired current snapshots cannot load.

Each accepted version is a single canonical JSON record named <20-digit sequence>-<snapshot SHA-256>.json, containing original canonical snapshot bytes, detached signatures, key-configuration digest, acceptance time and checkpoint. Cooperative readers/writers acquire an exclusive .lock directory. The newest sequence is authoritative; duplicate sequences, unexpected files, a corrupt latest record or invalid signature fail closed, never fall back. The previous record is reauthenticated at its stored acceptance time before accepting a successor, while the new snapshot is verified at current time. Lower sequences and same-sequence different hashes are rejected; identical versions are idempotent. Clock earlier than prior acceptance is rejected. One private directory is one research stream; use separate directories for separate streams. No automatic network updates.

Writes use a temporary same-directory file, file Sync and an atomic no-replacement hard link to the final filename. This requires local hard-link support. No active-pointer/checkpoint split. Directory fsync and power-loss durability are not implemented. A process crash can leave .lock or .pending files; the loader refuses unexpected files. Inspect state manually with all processes stopped before removing a stale lock or incomplete temp file. Never delete accepted history to recover from an error. Maximum 128 accepted records, approximately 64 MiB + 128 KiB per record; no automatic pruning. State directory and parents must be under trusted local control; local deletion, backup restoration, hostile mutation or changes to independently supplied pins/time are outside this protection. The journal is not tamper-proof hardware state. Older records are not all reverified on every load.

```sh
trust-registry snapshot install-research --state "$HOME/registry-research" --public-key research-public.pem --signature research.sig.json --threshold 1 --at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" --bootstrap local-snapshot.json
trust-registry snapshot load-research --state "$HOME/registry-research" --public-key research-public.pem --threshold 1 --at "$(date -u +%Y-%m-%dT%H:%M:%SZ)"
trust-registry snapshot find-installed --state "$HOME/registry-research" --public-key research-public.pem --threshold 1 --at "$(date -u +%Y-%m-%dT%H:%M:%SZ)" --fingerprint HEX
```

Subsequent install omits --bootstrap. No private signing keys in installation state. LoadResearch reauthenticates latest bytes and produces a detached view supporting Find, Search, Policy(id,version), VerifyLocalPath. Policy documents are decoded into copies; exact version is mandatory; path verification uses the embedded local policy and cannot accept a knowledge time after loading. No arbitrary caller policy substitution. Inventory is staged only in private temporary directories for indexing/path validation; cleanup is best effort. Reopen with current time for a new verification session; an existing view does not automatically expire or reload. No signer certificate is persisted by the loader. All trust statuses remain NOT_ESTABLISHED, releaseAuthenticated false. No production bootstrap, root rotation, authenticated freshness/latest discovery or TUF integration. Tests added but not executed while CI is suspended.
