# Static publication pipeline (local staging only)

The public Explorer is still a research preview, not a trust bootstrap. This separate release workflow uses a fresh Explorer build plus reviewed ledger records. It never deploys, invokes Cloudflare APIs, reads credentials from Cloudflare, or uses D1/KV/R2/DO. Explicit authorization of branding and publication rights is still required. Do not enable automatic Workers Builds for the production release: the preview build clears dist and does not carry TUF history. Preview-only redeployment to trust.m78u.com after publishing would remove release assets. Use one manual, reviewed deployment stream, no gradual traffic splits or rollback to older assets. Keep release-dist and private receipts outside Git; a new directory is required for each build (move previous staging after preserving its receipt).

Every historical ledger record must have valid independent public release approval checked at its build time, matching private approval/dossier digests; the current head must additionally be current at preparation. Uncredentialed historical research ledgers cannot be published by this command. Never reset an already-public stream; migrate under independent review before use. All numbered roots, snapshots/targets metadata, and digest-named targets are retained byte-for-byte. Only the latest timestamp is included. No historical timestamp, private dossier, evidence, authority file, ledger or manifest is copied into the website. Previous deployment manifest is a local assertion pinned by the operator; it is not proof of live delivery. First deployment requires explicit --first; subsequent deployments require prior manifest/pin. No removal of previous assets, rollback of sequence, conflicting same-sequence head or changed immutable paths. Same-head re-export allowed for site-only changes. All files are allowlisted, budgeted (512 files, 192 MiB total, 25 MiB per file), and hashed. No automatic R2 fallback, sharding, or archival on limit hit. The target can exceed Cloudflare's 25 MiB limit before this gate; reject rather than modify signed bytes.

1. Build/test Explorer (`cd web && npm test && npm run build`). Review local build and source/branding.
2. From built tuf-publish executable, prepare (paths illustrative, use actual independent pins/current UTC):
```sh
tuf-publish static-prepare --ledger PRIVATE_LEDGER --root-sha256 INITIAL_PIN \\
  --authority PRIVATE_AUTHORITY_JSON --authority-sha256 AUTHORITY_PIN \\
  --expected-head LEDGER_HEAD_PIN --explorer web/dist --first \\
  --now CURRENT_RFC3339 --out web/release-dist --manifest-out PRIVATE_MANIFEST.json
```
Later replace --first with --previous-manifest LAST_DEPLOYED_MANIFEST --previous-manifest-sha256 LAST_PIN. Retain the printed manifestSHA256 independently. Output is a full fresh static collection, not just changed files; the report counts new/changed/unchanged and candidate bytes by path/content against prior manifest. Wrangler's content-addressed upload negotiation determines actual missing assets; numbers are estimates, not measured Cloudflare billing. Do not upload only a delta directory. File writes put timestamp last locally; a complete immutable asset deployment switches visibility together, not an in-place remote overwrite. Local interrupted output must be discarded, not deployed.
3. Immediately before deploying, use `tuf-publish static-check --assets web/release-dist --manifest PRIVATE_MANIFEST.json --manifest-sha256 PIN --now CURRENT_RFC3339`. Verify exact membership, hashes and timestamp freshness. This checks bytes against an independently pinned preparation receipt, not all cryptography again. Prepare already verified signatures. Do not deploy if time has expired. Review the separate `web/wrangler.release.jsonc` (no script, binding, redirects, custom 404 handling, or dynamic worker). Pin and verify Wrangler version externally. Operator explicitly runs `cd web && wrangler deploy --config wrangler.release.jsonc` only after all release gates. This is not an automatic deploy workflow. Check live timestamp and versioned file hashes/headers and test strict CLI from an independently provisioned root and review authority; retain prior manifest only after successful verification. Never deploy a prior version to recover; roll forward with new approved sequence.
4. Public URLs: https://trust.m78u.com/tuf/metadata/ and https://trust.m78u.com/tuf/targets/. Immutable file headers use one-year max-age; timestamp no-store; Explorer default revalidation. Signed expirations and client rollback checks remain mandatory regardless of cache. Header overrides detach old Cache-Control first, no conflicting directives. Nonexistent numbered root must be HTTP 404; no SPA fallback. Actual edge headers and status require deployment smoke tests. Cloudflare cache rules must not override timestamp freshness. Static requests free per current docs; zero runtime Worker/DB operations is an architecture goal, not measured usage. No automatic extra paid services. Retain source and release receipts and independently protect head pins.

References: https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/ ; https://developers.cloudflare.com/workers/static-assets/headers/ ; https://developers.cloudflare.com/workers/static-assets/direct-upload/ . Synthetic tests cover history, delta, path allowlist, file/total budget, modified/extra assets and wrong baseline pin. Tests not executed; auto PR CI stays disabled. No real data, deploy, or production trust.
