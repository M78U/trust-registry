# Experimental offline TUF publisher

The initial root (version 1) contains four disjoint Ed25519 role key sets, independent thresholds and consistentSnapshot=true. CreateRoot uses only root private keys; other roles supply public keys. BuildRepository receives independently pinned root metadata plus Targets, Snapshot and Timestamp signers; root private keys are not needed. All signatures are generated and checked with upstream go-tuf/sigstore. Key sets are capped at 16 per role. No private keys are written by the publisher. Use independently protected offline keys, not GitHub or Cloudflare secrets. CLI accepts local unencrypted PKCS#8/SPKI PEM for research; secure hardware signing and key rotation are not implemented.

The input must pass existing Registry snapshot semantic validation. Metadata version is explicitly equal to the positive Registry sequence, with explicit current UTC time and expiry ordering now < timestamp <= snapshot <= targets <= root and targets <= Registry expiry. Root version 1 only. Each role signs its own metadata; snapshot and timestamp link exact serialized child metadata size/SHA-256. A static candidate contains metadata/1.root.json, metadata/<version>.targets.json, metadata/<version>.snapshot.json, metadata/timestamp.json and targets/<sha256>.registry-snapshot.json. This matches the experimental client. Output is a new local directory; not a live repository. A failed write may leave partial staging output; discard that staging directory after inspection. No automatic upload, activation, version ledger, rotation or pruning. Operators must maintain strictly increasing publication versions, preserve previously published immutable paths, and publish mutable timestamp last only after independent review. Never overwrite a live immutable version or reissue different contents under the same version. Do not deploy until version-state and integration tests are complete.

Example commands (all key files already independently created outside Git; use disposable research keys):
```sh
cd tools/tuf-client
go run ./cmd/tuf-publish root --root-public root.pub.pem --targets-public targets.pub.pem --snapshot-public snapshot.pub.pem --timestamp-public timestamp.pub.pem --root-key root.pem --expires 2027-01-01T00:00:00Z --out root.json
go run ./cmd/tuf-publish build --root root.json --root-sha256 INDEPENDENT_ROOT_SHA256 --version 1 --now 2026-11-27T00:00:00Z --targets-expires 2026-12-01T00:00:00Z --snapshot-expires 2026-11-29T00:00:00Z --timestamp-expires 2026-11-28T00:00:00Z --targets-key targets.pem --snapshot-key snapshot.pem --timestamp-key timestamp.pem --out repository-candidate local-snapshot.json
```
Repeat role-public and role-key flags and set role-threshold flags for multi-signature research. Use actual appropriate dates and independent root digest. No CA trust or redistribution permission follows from signing. Do not publish candidate snapshots containing unapproved CA material. The repository target can exceed Cloudflare Workers static asset size limits; choose approved sharding/distribution (e.g. R2) later, not automatic deployment.

The module remains experimental: Go 1.26/module proxy unavailable, go.sum not generated, no executed tests. New synthetic tests check upstream role signature verification, cross-role key reuse, hash links, sequence and unauthorized signers; full client/publisher roundtrip, key rotation, publication monotonicity, application rollback/installation, dependency lock and manual CI are outstanding. Automatic PR CI remains disabled.
