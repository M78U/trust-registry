# Offline certificate path validation

Two layers: registry.Store.VerifyPath checks an ephemeral end-entity against explicitly named inventory CA fingerprints; validation.VerifyLocalPath evaluates an unauthenticated local policy and supplies only currently locally authorized anchors and explicit intermediate candidates. Exact purpose match and explicit evaluation/knowledge times are mandatory. No automatic promotion of discovered issuers, no network or operating-system roots. Fresh non-system smx509 pools are always supplied, even for empty sets (empty anchor set yields NOT_ESTABLISHED before library verification).

The verifier uses gmsm/smx509 v0.45.0 Verify with explicit CurrentTime, EKU options and bounded constraint comparisons, including library signature, validity, path length, name constraints, policy processing and critical extension checks. It filters returned paths again against exact registry roles and the shared direct issuer checks (exact DER DN, AKI/SKI conflict, signature, CA constraints). Explicit anchors need not be self-signed; CA constraints and certificate signing usage are required where present. No leaf may be a CA or be reused as an anchor. Maximum 256 CA inputs, 32 MiB DER retained, 32 nodes per returned path and 256 returned chains; store validation precedes these bounds.

Technical profiles: signature (explicit digitalSignature or contentCommitment KU, library EKU Any; not a business-purpose check), timestamping (explicit signing KU and critical exclusive timeStamping EKU), code-signing (explicit signing KU and codeSigning EKU), client-authentication, server-authentication (explicit DNS name). Document-signing, electronic-seal-signing, seal-maker and device-authentication map only to generic signature until reviewed purpose-specific OIDs and constraints exist. No verified signer identity, document signature verification or timestamp token verification. No revocation or authenticated policy history. No claim of complete RFC 5280 conformance. The library may not enumerate every valid path; unsupported constraints/algorithms can cause rejection.

CLI exits nonzero for no valid technical path, but emits the diagnostic JSON. Exit zero indicates only VALID_UNDER_EXPLICIT_CA_SET; businessPurposeStatus and trustStatus always NOT_ESTABLISHED, releaseAuthenticated false, revocationStatus NOT_CHECKED. The generic signature profile expressly does not enforce chain EKU scope. Production consumers must never use exit status or pathStatus alone to grant trust. Keep signer data private.

Synthetic tests cover explicit roots and intermediates, missing/empty anchors, expiry, wrong profile, CA leaf, duplicate roles, no implicit time, SM2 and path length. Real CA research and independent evidence remain pending.
