# Client-side independent release authorization (experimental)

Private CA review and approval are not public. A separate compact public credential (max 16 KiB) is signed by the pinned RELEASE role threshold, after verifying the complete private dossier, artifacts and private approval. It includes only independent authority digest, exact initial/current root digests, Registry snapshot digest/sequence, exact three online metadata expiration times, private approval and dossier digests, asserted issuance time and release approver IDs/signatures. No private task IDs, notes, evidence bytes, URLs or private keys. Public verification attests that the configured release keys approved this exact distribution; it does not independently prove the private reviewers' evidence conclusions. The private approval window controls issuance/signing/build, not subsequent client validity. The public credential expires at the signed timestamp expiry. All times and root pins must be reviewed by signers; no remote key use.

Use review prepare-public with same private flags as authenticate-approval (--dossier, --evidence, --authority, --authority-sha256, --approval, --at) plus --initial-root-sha256, --root-sha256, --targets-expires, --snapshot-expires, --timestamp-expires, --out NEW and exact snapshot positional file. Then review sign-public with same private flags plus --credential PREVIOUS --id APPROVER --key PKCS8.pem --out NEW, repeated until threshold. Use exact output as --public-credential FINAL in tuf-publish build-reviewed or build-ledger, with identical root, snapshot and expiry options. Publisher rechecks private approval, credential and all root role-key separation. The credential is embedded as a base64 canonical payload in the existing signed Targets custom field; the five ordinary staging files (plus historical roots) are unchanged in number. Ledger stores it as part of exact signed Targets bytes. No extra request or cloud write.

Strict tuf-fetch requires both --authority LOCAL_JSON and --authority-sha256 INDEPENDENT_PIN in addition to existing root pin. Explicit bootstrap into a new state directory; cannot silently downgrade or change authority because exact state configuration pins this mode. Existing research state remains research-only; do not reset or migrate a production checkpoint to bypass rollback protection. Fetch checks public approval before target download and rechecks expiry at actual completion time, rejects missing/malformed/expired/wrong-context credential, checks independent TUF/review key separation and exact sequence. tuf-load with same independent authority flags verifies the credential from installed signed Targets metadata offline; ordinary load refuses a strict state. Installed record remains unchanged in schema, no separate public credential state file. All prior TUF signature/expiry, cache/archive and installed sequence checks remain. Download-only refresh still lacks persistent application rollback protection, use --install. Local state and pins must be protected; no external anti-rollback proof or authority rotation.

Cloudflare: public static Targets metadata carries the receipt. Extra HTTP operations per refresh: 0; extra D1 rows, KV/R2/DO operations or Worker executions introduced: 0. Client verification entirely local. No online approval service, per-user storage, telemetry or deployment. Do not weaken timestamp expiry or rollback for cache savings. Public credential adds bounded metadata bytes only. Existing reviewed/research modes without credential remain deliberately available, not suitable for strict clients. ReleaseAuthenticated remains false and trustStatus NOT_ESTABLISHED; new releaseApproval report separately marks pinned release threshold verified, privateEvidenceVerified false. No real CA authorization, keys or production release. Synthetic tests added, Go tests not executed, PR CI stays manual-only.
