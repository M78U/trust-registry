# Local research snapshot format v1

An unsigned deterministic JSON envelope for local research and testing only. It is not a production distribution format or a trusted registry. No publication, upload, release tag, automatic installation or redistribution grant. Real CA bytes and policy data may be restricted; keep output private. The caller explicitly selects all policy documents and source revision (an assertion, not verified Git state).

The envelope is compact Go struct-order JSON plus LF. Manifest fields: schemaVersion, kind LOCAL_RESEARCH_SNAPSHOT, positive sequence, 40 lowercase hexadecimal sourceRevision, explicit UTC createdAt/expiresAt (expiry strictly later than creation), sorted files (path, byte size, SHA-256). Payload is an ordered array of path and standard base64 data. The manifest is independently serializable with ManifestBytes, and its SHA-256 is reported separately from the complete envelope SHA-256. This is a versioned serialization contract, not RFC 8785 JCS. Same exact inventory, documents (including internal array order), sequence, revision and times produce identical bytes independent of input document ordering. No ambient clock or ZIP timestamps.

Allowed paths: certificates/<DER SHA-256>.der and .json; provenance/<record SHA-256>.json; policies/<canonical document SHA-256>.json. No other names, paths or input file types. Canonical inventory JSON is retained; policies are re-serialized compactly. No personal signer certificates, private keys, source original files, arbitrary store-root files or website assets. Build validates input and revalidates serialized output.

Verify requires exact canonical envelope encoding and exact sorted manifest membership, size and hash for every file. Duplicate/unknown fields, changed case, noncanonical base64, extra/omitted payload and path traversal fail. For semantic checking, only fixed validated paths are written to a newly created private temporary directory, checked using existing inventory and policy validators, then removed. Nothing is extracted into caller-selected directories. Temp cleanup is best effort; interruption may leave temporary research bytes. Local filesystem and caller-controlled inputs assumed. Limits: 8192 files, 32 MiB decoded payload, 48 MiB envelope, 1 MiB DER, 64 KiB inventory JSON, 4 MiB policy document, 256 policies. Store validation precedes export caps; this is not a global store-memory limit. Verification buffers envelope and decoded payload, not a streaming parser.

An optional caller-pinned manifest hash only checks equality; provenance authenticity, completeness relative to other snapshots, sequence monotonicity, freshness, historical consistency and release authorization are not checked. A forged internally consistent snapshot can pass without an independently authenticated pin. Reports always have releaseAuthenticated false, trustStatus NOT_ESTABLISHED, freshnessStatus NOT_CHECKED, rollbackStatus NOT_CHECKED. Do not grant trust based on internal integrity or CLI exit status.

Next gate: evaluate TUF and define independent root bootstrap, signed metadata, expiry, persistent rollback state, key rotation and installation semantics before any production release. Explorer must consume an independently approved public projection, not publish this local envelope by default.
