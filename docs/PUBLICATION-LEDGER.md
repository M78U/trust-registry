# Persistent reviewed-build ledger (experimental)

This is a private local **build** ledger, not a log of online release acceptance. Use a dedicated protected directory outside Git and web assets. All state lives in immutable numbered JSON records (00000000000000000001.json, etc.), one exact signed repository per record. A record includes the exact five TUF staging file contents (through evidence), snapshot identity, asserted build time, authority/approval/dossier digests and previous record SHA-256. It does not retain private keys, private evidence artifacts or the review dossier. Approval digests are local recorded assertions, not independently verifiable reviewer signatures on ledger records; the full approval is verified before each new commit. Retain those inputs separately for audit.

First build requires --bootstrap, sequence 1, nonexistent directory with existing parent. Later builds require existing nonempty ledger and exact next sequence; previous snapshot is selected internally. Root and authority pins must remain fixed throughout a ledger. Every read scans all records in sequence, checks canonical bytes and hash links, revalidates exact TUF metadata/target at each historical build time and checks snapshot transition rules. No fallback, gaps, overwrite, reset, clock rollback or re-signing same sequence. Cooperating operations use exclusive .lock directory, a bounded temp file sync and same-directory no-replace hard link. Limits 128 records / 256 MiB encoded total / per-record bound. Requires local filesystem hard links. No directory fsync guarantee, hostile filesystem safety, external monotonic storage or proof that tail records were not removed. Retain independently protected latest receipt RecordSHA256 and use --expected-head when operating; it detects truncation relative to that known head, not malicious alternate histories if the pin is stale. Without that pin, rollback by deleting suffix remains possible. No automatic archival/pruning or key rotation. Directory creation or interruption may leave an empty directory, .lock or .pending files; inspect and recover manually. Never blindly delete a ledger or reset an existing stream.

Use build-ledger with all build-reviewed flags except --out and --previous/--previous-sha256, instead pass --ledger PRIVATE_LEDGER and --bootstrap for first build. For later builds omit --bootstrap and pass --expected-head LAST_RECEIPT_HASH. It emits LOCAL_REVIEWED_BUILD_COMMITTED only after local commit. It does not create a live/staging output directory. Then:

```sh
tuf-publish ledger-export --ledger PRIVATE_LEDGER \\
  --root-sha256 INDEPENDENT_ROOT_PIN --authority-sha256 INDEPENDENT_AUTHORITY_PIN \\
  --expected-head LAST_RECEIPT_HASH --now CURRENT_RFC3339 --out NEW_STAGING_DIR
```

Export acquires the lock, revalidates current head at actual current time, returns exact previously signed bytes and writes a fresh output directory. Approval validity is checked at build, not export; TUF metadata and snapshot must still be current. If export is interrupted discard partial staging directory and export to a new path while metadata remains valid. Expired head cannot be exported; build a new approved consecutive snapshot. Exported files are not uploaded, and the receipt cannot prove any client received them. Coordinate external upload and retention; don't serve research mode output. Direct experimental build/build-reviewed remain separate, not enforced production boundaries. No reviewed release client protocol yet. All receipts releaseAuthenticated=false and trustStatus=NOT_ESTABLISHED.

Synthetic tests extend reviewed publisher scenario with sequence 1/2, exact byte export, repeat bootstrap, stale pin, lock, expiry and missing-history detection. Go tests not executed; automatic PR CI remains disabled.
