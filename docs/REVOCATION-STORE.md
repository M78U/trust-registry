# Private revocation evidence store and path integration

Use a separate protected local directory, not the CA inventory or a Git checkout. OCSP and CRL data can include personal certificate identifiers. No source data, OCSP serials or local evidence are added to public snapshots or Explorer. `revocation-store init` creates a nonexistent directory (parent exists); never implicitly reset. Import accepts one CRL (DER or PEM) or one OCSP DER, validates parsing, and stores exact DER in a canonical JSON record named <DER SHA256>.json with first asserted observation time, source label, type, size and UNVERIFIED_LOCAL_OBSERVATION. Source/recording time are local assertions, not receipt proof or issuer signature verification. Repeat DER imports are idempotent, retain first observation and never change metadata. List returns metadata only. Signature/profile checks still occur against an explicit issuer pair at evaluation time.

All reads and imports serialize cooperating callers via .lock directory. Entire store is checked for canonical bytes, filename/hash consistency, bounds and parseability before use. Limits: 32 records, max 16 CRLs / 16 OCSP responses, 16 MiB aggregate DER each, 50,000 total CRL entries, 1 MiB per OCSP. A complete record is file-synced and published with a same-directory hard link (no replacement); needs filesystem hard-link support. No directory fsync or hostile filesystem guarantees. Interrupted operations may leave .lock or .pending files; inspect manually, do not automatically reset. No prune/GC, multiple observations, authenticated history, or proof of omitted evidence. Protect directory, parents and clock; deleting or altering metadata is not detected by a trusted external checkpoint. The cutoff excludes observations recorded after knownAt, in addition to the signed evidence issuance cutoff enforced by EvaluatePair; even hidden malformed records fail closed.

```sh
trust-registry revocation-store init --store ./private-revocation
trust-registry revocation-store import --store ./private-revocation --kind CRL --recorded-at 2026-11-27T00:00:00Z --source "local issuer download" issuer.crl
trust-registry revocation-store list --store ./private-revocation
trust-registry verify-path --registry ./local-registry --policy local-policy.json --purpose document-signing --at 2026-11-27T00:00:00Z --known-at 2026-11-27T00:00:00Z --revocation-store ./private-revocation signer.cer
```

Use actual observation times. `VerifyLocalPathWithRevocation` first loads a detached evidence set and uses the original exact-policy technical path verifier; no change to certificate path selection or authorization. Checks every returned chain's direct child/issuer pairs, excluding terminal anchor. Identical pairs are checked once and referenced by zero-based pairIndices. Max 128 unique pairs and 32 MiB DER cache; excess fails closed. Per-chain summaries and overall worst-risk status are independent of path validity. A revoked indication on one possible path is not a proof that every path is revoked. Historical revoked indications are separate. CLI returns nonzero on no path, incomplete, conflicting, revoked or historical revoked indication; zero only indicates supplied evidence contains non-revoked indications, never production trust. No path returns NO_VALID_PATH; empty evidence store yields incomplete when path exists. Existing verify-path without flag is unchanged. Loaded snapshot SDK supports same operation with the exact installed policy, separate local evidence and cutoff <= load time. No automatic network, CRL distribution point coverage, freshest evidence or delegated responders. Synthetic three-certificate test covers leaf/intermediate separation, first observation, cutoff and corrupted record rejection. Go tests not executed; automatic CI remains disabled.
